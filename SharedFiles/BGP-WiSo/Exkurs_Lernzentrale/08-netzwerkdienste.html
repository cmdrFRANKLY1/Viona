DHCP liefert typischerweise IP-Adresse, Maske/Präfix, Standardgateway, DNS-Server und Lease-Dauer. Vor Ablauf versucht der Client die Lease per DHCPREQUEST zu verlängern. ipconfig /release gibt sie frei, ipconfig /renew fordert eine neue Konfiguration an.

3. DNS: hierarchische Namensauflösung

Ein rekursiver Resolver beschafft die Antwort für den Client und nutzt seinen Cache. Autoritative Nameserver liefern verbindliche Daten für ihre Zone. Ohne Cache fragt der Resolver schrittweise Root-, TLD- und autoritative Server.

4. Routingentscheidung und Gateway

  1. Ziel-IP mit eigener Netzmaske vergleichen.
  2. Liegt das Ziel lokal, wird dessen MAC-Adresse per ARP beziehungsweise Neighbor Discovery ermittelt.
  3. Liegt es in einem bekannten fremden Netz, gilt die spezifischste passende Route.
  4. Fehlt eine spezifische Route, wird die Default Route über das Standardgateway verwendet.
  5. Fehlt auch sie, ist das Ziel nicht erreichbar.

5. NAT, PAT und Portweiterleitung

Statisches NAT

Feste 1:1-Zuordnung zwischen interner und externer Adresse.

Dynamisches NAT

Temporäre Zuordnung aus einem öffentlichen Adresspool.

PAT

Viele interne Verbindungen teilen eine öffentliche Adresse und werden über Ports unterschieden.

Portweiterleitung

Eingehender Verkehr auf einem öffentlichen Port wird gezielt an einen internen Dienst geleitet.

NAT ist Adressübersetzung, keine Firewall. Eine zustandsbehaftete Firewall entscheidet anhand von Regeln und Verbindungszustand, welcher Verkehr erlaubt ist.

Häufige Fehler

  • DNS wird für die Vergabe der IP-Adresse verantwortlich gemacht.
  • Gateway wird auch für ein Ziel im eigenen Subnetz benutzt.
  • NAT wird als Sicherheitsmechanismus mit einer Firewall gleichgesetzt.
  • Eine private Adresse wird als gar nicht erreichbar bezeichnet; intern ist sie sehr wohl routbar.
  • Nur „Ping geht nicht“ wird geprüft, ohne Namen, IP, Route und Port getrennt zu testen.

Stufe 3

Ein interner Webserver soll von außen erreichbar sein. Erkläre notwendige NAT-, Firewall- und DNS-Konfiguration und je ein Risiko.

Öffentlicher DNS-A/AAAA-Record zeigt auf die externe Adresse. Portweiterleitung beziehungsweise statisches NAT leitet zum internen Server; die Firewall erlaubt nur den benötigten Port. Risiken: öffentlich erreichbarer Dienst, Angriffsfläche, fehlerhafte TLS-/Patch-Konfiguration.

  • Konfiguration, Namensauflösung, Routing und Übersetzung getrennt prüfen.
  • DNS-Record passend zur Aufgabe wählen.
  • Bei Routing immer die spezifischste Route beachten.
  • NAT und Firewall fachlich trennen.
