DHCP: Wie Computer eine IP bekommen DHCP: How Computers Get an IP

DHCP (Dynamic Host Configuration Protocol) ist der Grund, warum du dich einfach in ein WLAN einloggen kannst und sofort Internet hast. Ohne DHCP müsstest du jedem Gerät manuell eine IP-Adresse, eine Subnetzmaske und einen Router zuweisen. Es nutzt im Hintergrund UDP (mehr dazu in cheatSheetTCPandUDP.html). DHCP (Dynamic Host Configuration Protocol) is the reason you can just connect to Wi-Fi and instantly have internet access. Without DHCP, you'd have to manually assign an IP address, subnet mask, and router to every single device. Under the hood, it uses UDP (learn more in cheatSheetTCPandUDP.html).

2. Der D.O.R.A. Prozess 2. The D.O.R.A. Process

Wenn ein Gerät dem Netzwerk beitritt, durchläuft es vier Schritte, um eine IP-Adresse zu bekommen. Das nennt man den DORA-Prozess. Da der Client am Anfang noch keine IP hat, schreit er oft ins gesamte Netzwerk (Broadcast). When a device joins a network, it goes through four steps to get an IP address. This is called the DORA process. Since the client doesn't have an IP at first, it often shouts to the entire network (Broadcast).

Discover Client $\rightarrow$ All

Der Client ruft ins Netzwerk: "Hallo? Ist hier ein DHCP-Server? Ich brauche eine IP-Adresse!" Dies passiert als Broadcast (an alle), weil er noch nicht weiß, wo der Server ist. The client shouts to the network: "Hello? Is there a DHCP server here? I need an IP address!" This is sent as a Broadcast (to everyone) because it doesn't know where the server is.

Offer Server $\rightarrow$ Client

Der DHCP-Server antwortet: "Hallo! Ich bin ein Server. Ich hätte die IP 192.168.1.50 für dich frei." The DHCP server replies: "Hello! I am a server. I have the IP 192.168.1.50 available for you."

Request Client $\rightarrow$ All

Der Client antwortet (wieder als Broadcast): "Super, ich nehme die 192.168.1.50!" Der Broadcast ist wichtig, damit andere potenzielle DHCP-Server wissen, dass der Client bereits versorgt ist und ihre eigenen Angebote zurückziehen können. The client replies (again as a Broadcast): "Awesome, I'll take 192.168.1.50!" The broadcast is important so that other potential DHCP servers know the client has accepted an offer and can cancel theirs.

Acknowledge Server $\rightarrow$ Client

Der Server bestätigt final: "Alles klar, die IP gehört dir! Hier sind noch Infos wie Gateway und DNS, und du darfst die IP für 24 Stunden behalten." The server finally confirms: "Alright, the IP is yours! Here is the Gateway and DNS info, and you can keep this IP for 24 hours."

3. Lease Time (Der Mietvertrag) 3. Lease Time (Renting the IP)

IP-Adressen werden nicht verschenkt, sie werden vermietet. Die Dauer dieser Miete nennt man Lease Time. Wenn du das Netzwerk verlässt, kann der Server die IP nach Ablauf der Zeit jemand anderem geben. IP addresses are not given away forever; they are leased (rented). The duration is called the Lease Time. If you leave the network, the server can give the IP to someone else once the lease expires.

Renewal (Verlängerung) Renewal Process

Ein Gerät wartet nicht, bis die Zeit komplett abgelaufen ist. Es versucht die Miete schon vorher zu verlängern: A device doesn't wait until the time completely runs out. It tries to renew the lease early:

$T_1$ (50%)
Nach der Hälfte der Zeit fragt der Client den Server direkt (Unicast): "Darf ich die IP behalten?" At 50% of the lease time, the client asks the server directly (Unicast): "Can I keep this IP?"
$T_2$ (87.5%)
Falls der Server bei $T_1$ nicht antwortet, gerät der Client leicht in Panik und schreit bei 87.5% der Zeit ins ganze Netz (Broadcast): "Kann BITTE irgendein Server meine IP verlängern?" If the server didn't reply at $T_1$, the client panics slightly and shouts to the whole network (Broadcast) at 87.5% of the time: "Can ANY server PLEASE renew my IP?"

4. Ports & UDP 4. Ports & UDP

DHCP muss schnell sein und funktioniert auch dann, wenn noch keine stabile Verbindung existiert. Deshalb nutzt es das UDP-Protokoll (genau wie in cheatSheetTCPandUDP.html erklärt, gilt hier "Fire and Forget"). DHCP needs to be fast and must work even before a stable connection is established. Therefore, it uses the UDP protocol (just as explained in cheatSheetTCPandUDP.html, it's "Fire and Forget").

Role Protocol Port
DHCP Server (Router) UDP 67
DHCP Client (Laptop/Handy) UDP 68

Eselsbrücke: Der Server (67) ist älter/kommt zuerst, der Client (68) ist jünger/kommt danach. Mnemonic: The server (67) comes first numerically, the client (68) comes second.
